## 5. 双向同步（AEOS.Event.V1）

**契约**：13 种事件 = 6 实体 × {upserted, deleted} + `dictionary.upserted`（`app/contracts/aeos.py`）。实体：customer / inquiry / quote_library / order / sample / feedback。

**幂等键**：`{target_system}:{event_type}:{object_id}:{fingerprint}`
- `fingerprint = sha1(canonical(event 整包，剔除 occurred_at / event_id / trace_id / idempotency_key))[:16]`（对齐 EBMS 整包口径，勘误值：Order `SO20261017001#1`→`e44519e77910896a`、Inquiry `JFX20261017001`→`6cf954c39baab26c`）。
- canonical = UTF-8、键排序、无空格紧凑 JSON；标量按 JSON 原生字面量（bool→`true`/null→`null`/int→数字），datetime/date→ISO；金额/数量保留字符串原样，规避浮点漂移。

**出站（CRM → EBMS）**：任一实体创建/更新/删除后，`ebms_sync.emit_upsert / emit_delete` 构造事件入队 Outbox（`IntegrationOutbox`，`services.ebms.emit_entity_event` 投递），不直写 EBMS 库。

**入站（EBMS → CRM）**：`services/ebms_ingest.py` 消费事件，冲突规则（读法 A：EBMS 一次性迁移源，CRM 长期 Owner）：

| 规则 | 触发 | 行为 |
|---|---|---|
| OWNER_KEPT | 对象已存在，入站试图改写 CRM 拥有字段 | 仅应用 `EBMS_OWNED_FIELDS`（= `external_id`），其余字段记录 `SyncConflict(resolution=OWNER_KEPT)`，不改本地 |
| LOCKED | 订单 `user_status_locked=True` | 仅跳过 `status` 覆盖并留痕（resolution=LOCKED），其余字段照常按 Owner 规则同步（对齐 EBMS） |
| STALE | `occurred_at < last_sync_at` | 迟到事件丢弃 |
| DELETE 保护 | `sync_status=PENDING`（本地有未同步出站变更） | 拒绝删除 |
| 幂等 | 同幂等键重复投递 | 返回 duplicate，不重复写入 |

入站鉴权：`Authorization: Bearer <EBMS_INBOUND_TOKEN>`；令牌未配置返回 503，令牌错误返回 401，契约校验失败返回 422（批量先整体校验，避免半截写入）。

## 7. 业务规则落地：M2.5/M2.6 + 16 项口径回调（PAND-288 / PAND-289）

**签批口径（PAND-285「默认」=A）**：M2.5-D1~D5、M2.6-D1~D4 全部按推荐默认落地。

### 7.1 成本结构（M2.5）

- 成本并轨 9 项：以 CRM 8 项为录入口径，新增 `loss_cost`（损耗成本，默认 0）；`base_cost` = 9 项合计（4 位）。
- EBMS 口径映射（`app/services/pricing.py` `EBMS_TO_CRM_COST_FIELDS`）：`process_cost→labor_cost`、`accessory_cost→packaging_cost`、`estimated_loss→loss_cost`。
- 报价公式统一 EBMS：`final_price = base_cost × (1 + profit_rate) × discount_rate`（对外 2 位）；规则引擎只调利润率（动作 `margin`/`margin_delta`），不再直接乘最终价。
- 规则动作迁移（PAND-298）：既有 `price_multiplier` 规则等价转换为 `margin_delta = price_multiplier − 1`（种子「欧洲市场系数 1.05」→ `margin_delta=+0.05`）；运行期再遇到 `price_multiplier` 会记录告警并忽略。
- `floor_price` = 单位成本（`base_cost / 明细数量合计`，零利润底线）。
- 取整：成本/中间值 4 位、对外报价 2 位；汇率在报价创建时快照（16-10 配置项 `system_config.pricing.exchange_rate`，默认 7.25，落 `quotation.exchange_rate`）。
- 利润率全局默认 0.2（`DEFAULT_PROFIT_RATE`），支持规则覆盖。

### 7.2 折扣审批（M2.6）

- 触发三档（`app/services/approval.py` `steps_for`）：`discount_rate=1` 免审 → `[]`；`[0.95,1)` 经理 → `["manager"]`；`<0.95` 总监 → `["boss"]`（阈值含等号，0.95 归经理档）。
- 折扣率定义：`∈(0,1]`（Schema `Field(gt=0, le=1)`），相对「标准价」=`base_cost × (1 + profit_rate)`。
- 金额门槛（M2.6-D1 附加条件，PAND-298）：`system_config` 键 `approval.discount_amount_threshold_enabled`（默认 `false`）、`approval.discount_amount_threshold`（默认 `50000`）。关闭时三档判定与上一条完全一致；开启后金额严格大于门槛自动升一级（免审→经理、经理→总监，总监已是最高档）。核价以 `total_cost`、报价以 `total_amount` 判定。
- 未批行为：未批不得生成/导出报价单（`generate-pdf`/`export-excel` 要求 `APPROVED/SENT/ACCEPTED`），仅可保存核价草稿。

### 7.3 数据模型与迁移

- `pricing_record`：加 `loss_cost`（默认 0）/ `base_cost` / `final_price` / `discount_rate`（默认 1）。
- `quotation`：加 `discount_rate`（默认 1）。
- `approval_instance`：加 `discount_rate`（审批折扣率快照）。
- 迁移：`backend/alembic/versions/4c1f8a2b9d3e_m25_m26_cost_structure_and_discount.py`；PAND-298 数据迁移 `b8f2c4d6e8a1_pand298_rule_actions_and_config.py`（规则动作转换 + 新增配置项）；迁移链 `e9f3a1c8b2d4 → 4c1f8a2b9d3e → b8f2c4d6e8a1`（head）。

### 7.4 接口变更

- `POST /pricing/calc`：入参新增 `discount_rate`；出参新增 `base_cost / final_price / discount_rate`。
- `POST /pricing`：入参新增 `discount_rate`（默认 1）；`submit` 按折扣率三档生成审批链，`=1` 免审直批（询价→PRICED、商机→PRICING）。
- `POST /quotations/from-pricing`：快照汇率（取 `system_config.pricing.exchange_rate`，默认 7.25）、沿用核价 `discount_rate`；单位价 = `final_price / 明细数量合计`，**对外按 2 位舍入落库**（`_allocate_unit_price`，避免数量不整除产生 4 位价）。

- **导出 2 位（M2.5-D4，PAND-294 返工）**：报价单 PDF（HTML 与 reportlab 两条路径）单位价按 2 位渲染；xlsx 单位价按 2 位数值写入并设 `0.00` 数字格式；金额/合计仍为 2 位且 `小计 = Σ单价×数量` 口径不变。

### 7.5 16 项口径回调（16-06 / 16-09 / 16-15，PAND-289）

签批结论：#06=B、#09=B、#15=B，三项均已在合并基线 `9d311ae` 落地。

**16-06 交付逾期判定**（`app/services/ebms.py` `_overdue_days`）

- 有承诺交期 `promised_date`：以承诺交期为准，`promised_date < 判定日当日` 即逾期；逾期天数 = 判定日 − 承诺交期（最小 1 天），`basis="promised_date"`。
- 无承诺交期：回退代理规则「业务时间 `created_at` + `sla_days` < 判定日」，`sla_days` 默认 7（`DEFAULT_DELIVERY_SLA_DAYS`，入参范围 0~3650），`basis="sla"`。**`sla_days` 仅作无交期兜底，不参与有交期订单的判定。**
- 判定对象：未达已发货的推进态订单（`open / confirmed / procurement_ready / material_ready / packaging_done`）。
- 严重度：逾期 ≥30 天 `critical`、≥14 天 `high`、≥7 天 `medium`、其余 `low`（`SEVERITY_THRESHOLDS`）。
- 接口：`POST /api/v1/integrations/ebms/pilot-b/exception`，入参 `sla_days`（默认 7）/ `as_of` / `limit` / `deliver`；产出 `AEOS.Exception.V1`（`reason_code` 为交付逾期，`extra.basis` 标注判定依据）。

**16-09 订单状态同名映射**（`app/domain/state_machine.py` `EXTERNAL_ORDER_STATUS_MAP`）

- 入站映射：`completed→completed`、`closed→closed`（同名直映射）。
- `app/services/ebms_ingest.py` `_map_payload` 对 `Order.status` 应用该映射；未声明的状态按原值透传；CRM 订单状态机与终态规则（`completed / closed / cancelled`）不变。

**16-15 客户查重**（`app/api/v1/endpoints/companies.py` `_detect_duplicates`）

- 名称：去首尾空格、大小写不敏感后**精确匹配**，命中即「名称重复」（`suspected=false`，确定重复）。
- 税号：`tax_id` 相同即「疑似重复」（`suspected=true`）。
- 电话：联系人 `phone` / `mobile` 任一相同即「疑似重复」（`suspected=true`）。
- 疑似结果仅提示，必须由人工在「去重合并」弹窗确认主客户与合并对象（需 `customer:merge` 权限）；系统不自动合并。
- 客户导入走「名称 + 税号」去重：名称已存在跳过（原因「客户名称已存在」）；税号命中跳过并标记「税号已存在（疑似重复）」。

## 8. 客户域增强：线索 + 客户建档 + 联系人（PAND-312 / PAND-315）

依据 PAND-313 验收口径与 PAND-314 架构基线落地，覆盖线索新建/转化查重、客户档案补全与分组、联系人一人多客户关联三条主线。

### 8.1 线索管理（LEAD-02 / LEAD-03）

**字段扩展**（`lead` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `requirement_text` | Text（≤5000） | 具体需求内容 |
| `lead_level` | String(10)，默认 `B` | 线索等级：A 高意向 / B 中意向 / C 低意向 |
| `background` | Text（≤5000） | 初步背景调查 |
| `channel` | String(30)，默认 `OTHER` | 客户渠道分类（展会 / B2B / 官网询盘 / 客户推荐 / 自主开发 / 代理商 / 社媒 / 其他） |

**查重规则**（`app/services/dedup.py`，线索新建 + 转化为客户前各执行一次）

- **确定重复**：名称归一（去首尾空格、小写、压缩空白）相等；邮箱归一（小写）相等；电话归一（仅保留数字）相等。
- **疑似重复**：邮箱域相同且非免费邮箱域（`gmail.com` / `qq.com` / `163.com` 等 15 个常见免费域排除）；名称去除法人后缀（Ltd / LLC / GmbH / Co. / 有限公司 / 有限责任公司 等）后相等；公司名称/官网命中邮箱域。
- 查重范围：线索、客户、联系人三表；候选上限 20 条（`CANDIDATE_LIMIT`），超出置 `truncated=true`。
- 命中确定重复 → 409 拒绝，`data.candidates` 返回候选；命中疑似重复 → 同样 409，需填写 `non_duplicate_reason`（1~200 字）方可继续；新建接口强制传查重说明时需 `force=true` + `dedup_note`，说明以「（查重确认：…）」追加到备注。
- 新增 `POST /leads/check-duplicate` 供表单预检，入参 `name/email/phone/exclude_lead_id`。

**转化流程**（`POST /leads/{id}/convert`）

- 支持 `link_company_id` 直接关联既有客户（`linked_existing=true`，不再新建公司），或默认新建客户。
- 新建客户自动承接：`source`（线索渠道映射）、`company_background`（线索背景）、`remark`（「由线索 {lead_no} 转化」+ 非重复说明）。

## 9. 产品资料 + 商机流转 + 样品管理（PAND-316）

### 9.1 产品资料与标准报价（PROD-01 / PROD-02）

- 数据模型（`app/models/business.py`）：`product_document`（`product_id`、`doc_type`、`version_no`、`file_id` → `file.id`、`filename`、`size`、`is_current`；唯一约束 `product_id + doc_type + version_no`）与 `standard_quote`（`product_id`、`currency`、`qty_from`、`qty_to`、`unit_price`、`valid_from`、`valid_to`、`version_no`、`status`；唯一约束 `product_id + currency + version_no`）。
- 资料类型固定 5 类：销售资料 / 规格书 / 测试报告 / 认证文件 / 标准报价；文件版本号必填且同类型内唯一，可手工指定或留空自动递增（`v1`、`v2`…）；同类型仅一条 `is_current`，由 `services/product_assets.recompute_current` 在新增/改版本/删除后重算。
- 上传校验：白名单扩展名（pdf/doc/docx/xls/xlsx/ppt/pptx/png/jpg/jpeg/zip），单文件 ≤ 50 MB（`DOC_MAX_BYTES`）；超限或类型不符返回中文错误。
- 标准报价：币种取 `CURRENCIES`；数量区间 `[qty_from, qty_to)`（`qty_to` 为空表示无上限），同币种同版本唯一；对外状态由（存储态 + 有效期 + 当天）派生：生效中 / 未生效 / 已过期 / 已停用，停用报价不参与区间重叠校验。
- 按数量选价：`POST /products/{id}/standard-quotes/select` 在生效且数量命中的报价中取最高版本，未命中返回 404「无适用的标准报价」。
- 端点：`/products/{product_id}/documents`（POST 上传 / GET 分组 / PUT 改版本 / DELETE 软删）、`/products/{product_id}/standard-quotes`（POST / GET / select）、`/standard-quotes/{quote_id}/disable`；权限沿用 `product:view/update`。

### 9.2 商机流转（OPP-01）
